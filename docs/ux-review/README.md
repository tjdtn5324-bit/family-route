# 가족경로 사용성 점검 — 1차

이번 점검은 AI가 설정한 가상 사용자의 관점과 전문가 관점에서 수행한 검토다. 실제 고령자 다섯 명이나 실제 UI/UX 전문가가 앱을 시험하거나 발언한 결과는 아니다. 실제 화면과 소스 코드의 확인 범위를 구분한다.

## 확인한 화면

1. 새 여행방 시작: [화면](01-home.png). 큰 입력칸과 버튼은 알아보기 쉽지만 계정 로그인 필요성과 시연방의 12시간 만료를 실제 이용자가 이해하는지 확인이 필요하다. 현재 만료 조건을 생성 전 안내한다.
2. 초대 링크로 가족 참여: [화면](02-invite.png). 초대받은 사람에게 이름과 참여 버튼만 주요 흐름으로 표시한다. 별도 시연방에서 이름을 입력하고 참여가 완료되는 것을 확인했다. 오류 상태는 직접 확인하지 않았다.
3. 장소 저장·제안: [화면](03-place-feedback.png). 별도 시연방에서 부산역을 저장해 제안하고 성공 안내가 해당 장소 옆에 표시되는 것을 확인했다. 실패 상태, 다양한 화면 크기와 보조기기 실사용 검증은 남았다.
4. 차에 타서 연결: 코드에 영문·숫자 10자리와 입력 접근성 설명을 추가했다. 이번 캡처에서는 차량 화면 재검증을 완료하지 않았다.

## 가상 가족 테스터 5명

- 70대 부모: 초대받은 뒤 만들기와 참여 중 하나를 고르는 부담 → 초대 시 참여 화면 우선.
- 60대 여행 계획 담당자: 방을 바꾸면 기존 방으로 돌아오기 어려움 → 전환 전에 확인과 초대 링크 안내.
- 50대 운전자: 사용한 연결 코드를 반복 입력할 가능성 → 10분·1회용과 재발급 방법 안내.
- 70대 첫 스마트폰 사용자: 장소를 제안해도 변화가 보이지 않음 → 해당 장소 옆에 결과 표시.
- 60대 가족 구성원: 저장 해제나 방 전환이 의도치 않게 일어날까 걱정 → 삭제 및 방 전환 확인.

## 가상 전문가 5명

- 가족 여정: 초대 → 장소 모으기 → 차량 연결 순서 안내.
- 정보 구조: 초대받은 화면과 새 여행 만들기를 분리, 계정 링크 중복 축소.
- 상호작용: 검색 결과의 장소마다 저장·제안 성공과 실패를 인접 표시, 검색 입력에서 Enter 지원.
- 접근성: 차량 코드 입력의 화면 읽기 설명과 10자리 안내 추가, 휴대폰 입력과 버튼의 큰 크기 유지.
- 신뢰와 이해: 임시 가족방은 12시간 또는 서버 재시작 시 사라진다는 사실을 만들기 전과 방 안에 표시.

## 남은 검증과 한계

- 실제 고령 사용자 5명과의 과제 수행, 인터뷰, 보조기기·큰 글씨 설정 검증은 하지 않았다.
- 가족방과 공유 코스는 서버 메모리에만 있고, 서버를 끄면 사라진다. 장기간 여행 준비를 위해 영구 저장이 필요하다.
- 현재는 로그인 기본 화면이 영어이며, 실제 사용자 회원가입 및 오류 복구 사용성을 확인해야 한다.
- 이번 화면 이미지는 데스크톱 브라우저 캡처이며, 실제 휴대폰과 PLEOS 장치의 전체 화면 검증을 대체하지 않는다.

## 2차 재점검

- 만료된 가족방 정보를 가진 상태로 서버가 다시 시작되면 새 방 화면으로 돌아오도록 수정했다. 별도의 로컬 시연 서버를 다시 시작한 뒤 새 방 화면을 확인했다. 일시적인 네트워크 실패에는 기존 방 정보를 지우지 않는다.
- 차량에서 이미 방이나 경로를 만든 뒤에도 휴대폰에서 미리 준비한 다른 방으로 전환할 수 있도록 추가했다. 전환 시 현재 차량 화면의 내용이 바뀐다는 설명과 별도의 확인 버튼이 표시된다. 에뮬레이터에서 기존 방을 만든 뒤 전환 안내와 확인 버튼이 나타나는 것을 확인했다. 실제 다른 방 연결까지의 재검증은 남았다.
